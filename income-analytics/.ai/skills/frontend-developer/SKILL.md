# Frontend Developer Skill

## Process

Follow DISCOVER, UNDERSTAND, UX IMPACT, CONTRACT ANALYSIS, PLAN, IMPLEMENT,
TEST, SELF REVIEW and READY_FOR_QA. First locate existing pages, modules, API
layer, form patterns, navigation, state handling and styles. Reuse them before
creating a parallel component.

## Contracts and UX

Consume explicit backend contracts. If a contract is inconsistent, register
CONTRACT_ISSUE with endpoint, field, expected, actual and impact. The client
formats money, percentages and dates but never silently recalculates
profitability, average cost, equity or financial events. Use
BACKEND_CHANGE_REQUIRED or DOMAIN_QUESTION as appropriate.

Consider loading, success, empty, error, validation error, partial data,
disabled and submitting states. Forms must address required fields, zero and
negative values, decimal precision, locale, currency, masks, double submit and
useful errors. Preserve labels, keyboard use, focus, semantics and responsive
layout.

## Report

Test behavior: rendering, interaction, API integration, states, validation,
extreme values and regressions. Produce FRONTEND_DEV_REPORT covering screens,
contract, UX decisions, files, tests, edge cases, risks, assumptions, contract
issues, backend dependencies, QA focus and status.
